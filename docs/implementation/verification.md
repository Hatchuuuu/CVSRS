## Defects found by testing (and fixed)
1. `staff_get_child` raised on denial, rolling back its own audit row → now returns NULL (D4).
2. Fixture names that accidentally matched as duplicates hid a broken concurrent-merge test → fixtures made distinct and asserted.
3. `Origin: null` on same-origin form POSTs (see above).
4. M03: a dose rejected by rule A1 was re-flagged on every later rule of the same antigen → flagged once (D21).
5. M03: superseding a schedule version with a future start left no version in force until the start date (T31) → retired versions govern their own window (D26).
6. M03: shared mutable fixture payload across tests hid a test bug; UTC-vs-clinic-local date mismatch found by activation test (D27).
7. M04: negative stock movements failed on `INSERT ... ON CONFLICT` CHECK ordering → UPDATE-then-INSERT projection (D31).
8. M04: an accidental `TRUNCATE` in a test wiped the ledger — a real gap: append-only tables lacked statement-level guards → added (D30).
9. M06: appending an unknown literal to a `text[]` failed at runtime, fixed with `array_append`; the duplicate check now runs before the schedule check so users see the more useful message.
10. M07: the "anon can execute no public function" hardening test correctly failed when `verify_certificate` was added; the deliberate public allow-list (now three functions) was updated in the test.
11. M07: a first mutation attempt (`if false and A or B`) did not disable the check because of operator precedence and the tests still passed; the mutation was redone properly and then failed as expected.
12. M09: the cold-chain test for "excursion stays open" first failed because the test itself had logged an extra excursion and counted before it; the count now follows the reviewer rules (a reader cannot review their own reading).
13. M09: an initial SMS event rule let a stray "failed" callback overwrite "delivered"; delivered messages are now immune to later failure events (tested).
14. M09: the guardian view of a catch-up plan exposed the existence of staff-only fields (`statusNote: null`); staff-only keys are now omitted entirely for guardians.
15. M09: family-facing text contained two invented operational claims ("staff read these messages during clinic hours"); removed. Only clinic-authored wording may make such claims.
