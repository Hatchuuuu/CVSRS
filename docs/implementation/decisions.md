# Decisions and Interpretations

| # | Decision | Reason |
|---|---|---|
| D1 | Next.js 16 / React 19 / TypeScript 5.9 / Tailwind 4 / Zod 4 / Vitest 5; **npm** with committed lockfile | Latest supported majors as of 2026-09-29. TypeScript 5.9 rather than 7.x/6.x for ecosystem compatibility with `eslint-config-next`. npm chosen over pnpm to avoid pnpm 11 build-script approval friction |
| D2 | Tables in `public` with RLS + **no direct write grants**; all writes are `SECURITY DEFINER` commands with `search_path = ''`; audit/receipts/settings in non-exposed `private` schema | Blueprint BP30/BP31: transactional commands, explicit grants, non-exposed internals. Verified by grant-introspection tests |
| D3 | Identifiable staff reads go through audited commands (`staff_get_child`, `staff_search_children`), not table SELECT. Guardians read only their own linked rows via RLS | Read-audit requirement (BP30/BP32) |
| D4 | Denials that must be audited (`staff_get_child`, `resolve_qr`) **return NULL** instead of raising; the API maps NULL to 404 | An exception rolls back the audit row. Capability failures (`CV403`) raise and are therefore not audited in DB; API-level security-event logging is a future task |
| D5 | Custom SQLSTATEs `CV400/401/403/404/409/422` | Stable, mapped to HTTP codes; raw DB text is never sent to clients |
| D6 | Staff capability requires `aal2` (DB-enforced) via `private.settings.require_staff_mfa` (default true) | BP32 MFA for privileged roles; enforced where it cannot be bypassed by UI |
| D7 | Grants use a two-person rule; clinical grants require `grant.approve.clinical`; nobody approves own or self-requested grant | BP14 "technical admin cannot self-grant clinical privileges"; T32 |
| D8 | QR tokens are stored **hashed**; the raw token is returned once at issue time. Guardians "replace" a pass rather than re-display it | Limits impact of DB disclosure. Trade-off: guardian must keep/print the QR |
| D9 | Duplicate candidate detection is restricted to children enrolled at the same clinic; candidate visibility respects clinic scope | Prevents cross-clinic disclosure through duplicate review |
| D10 | Guardian self-registered child: relationship `provisional`, scope `identity_only`; enrollment `pending`/`review_only` until staff confirm | BP15.A; wrong-child and stranger-claim safety |
| D11 | Unknown birth date stored as precision `unknown` (never 1 January) | BP39 |
| D12 | Local verification uses a **project-local PostgreSQL cluster** (Laragon binaries, port 54329, trust auth, loopback only) plus a Supabase-compatible bootstrap; the Laragon instance on 5432 was deliberately not used (password not provided) | No Docker/Supabase CLI available. Gives real RLS/grant/transaction behaviour, not GoTrue/PostgREST/Storage/Realtime |
| D13 | ~~`local-dev` session shim~~ **Superseded 2026-10-04:** removed. Supabase Auth is the only identity source; local development runs a local Supabase stack (`npm run dev`) | A shim proved database rules but not authentication, and the blueprint forbids a local password system |
| D14 | System font stack with "Atkinson Hyperlegible" first; font not bundled | Licensing/self-hosting verification pending; avoids network font fetch at build |
| D15 | `Referrer-Policy: same-origin` (not `no-referrer`) | `no-referrer` makes browsers send `Origin: null` on form POSTs, which broke CSRF checks (found in live testing) |
| D16 | Rate limiting is per-instance memory | Shared store not chosen; recorded as a limitation before any production claim |
| D17 | TS strict incl. `noUncheckedIndexedAccess` for app code; tests/scripts typechecked under a relaxed second config | Signal vs. noise in test fixtures |
| D18 | No real clinical values anywhere. The only schedule is the test fixture `tests/fixtures/synthetic-schedule.ts` (automated tests only): invented antigens (`DEMO-ALPHA/BETA/GAMMA`) and deliberately arbitrary numbers, flagged `is_demo` | BP16 / prompt §7: do not invent medicine |
| D19 | The schedule engine is **plpgsql** (`private.evaluate_rules`, a pure function of rules + inputs), not application TypeScript | One authority usable inside future atomic administration transactions and for approval fixtures; DB tests exercise it directly |
| D20 | Rules carry `sequence_no`; predecessors must have a lower sequence | Makes the dependency graph acyclic by construction and lets the engine run in one ordered pass |
| D21 | A dose counts only if it meets **every** limit of the rule (min age, per-predecessor interval, max age, product); otherwise it is preserved, uncredited and reported once as "staff review needed". No grace periods | Grace-period/validity policy is clinical and unspecified; failing safe |
| D22 | Non-exact dates (month/year/unknown) and unverified evidence cannot credit doses; they surface as unresolved history / pending evidence | BP16, T09 |
| D23 | Verification of outside evidence adds revision N+1 (verified, `approved_by` = verifier); it never mutates revision 1 | Immutable clinical history (BP28.3) |
| D24 | Without an exact DOB every requirement is `staff_review_needed (birth_date_not_exact)`; a null-DOB child can still be evaluated for holds/evidence | "Unknown required inputs prevent exact recommendation" |
| D25 | `past_recommended_date` status when a target passed and the rule has no due-window end; `overdue` only when an approved window end has passed | BP16: never invent an overdue threshold |
| D26 | Activating a new version with a future start retires the previous one with `effective_to = start − 1`; lookups honour retired versions inside their own effective window. Manual retirement ends use immediately (`effective_to` = yesterday) | Found by tests (T31): old version must keep governing until the new one takes effect |
| D27 | Clinic-local calendar date (clinic timezone) is used for "today" everywhere in commands and tests; never the UTC date | Found by tests: UTC vs Asia/Manila mismatch near midnight |
| D28 | Guardian schedule view is computed on demand and not persisted; staff evaluation persists a hashed snapshot | Avoid guardian reads mutating clinical tables |
| D29 | Demo schedules can be imported/activated only while `private.settings.demo_mode` is true | Prevent fictional rules going live in a production configuration |
| D30 | Append-only tables also get statement-level `BEFORE TRUNCATE` guards (ledger, history, evaluations, credits, privacy records, receipts, audit) | A test accidentally wiped the ledger via TRUNCATE, which bypasses row triggers |
| D31 | Balance projection is updated with UPDATE-then-INSERT inside the ledger trigger, under the balance row lock; `on_hand >= 0` is a CHECK as last defence | `INSERT ... ON CONFLICT` validates the proposed row's CHECK before conflict resolution, so a negative delta failed spuriously (found by tests) |
| D32 | Stock quantities are `numeric` in the product's stock unit (containers); only single-dose presentations can be issued; conversions are exact numeric division | BP19 MVP checklist: multi-dose disabled until the vial workflow exists |
| D33 | Count adjustments: |delta| above `adjustment_auto_approve_units` (default 0 = all) is only proposed as a review case; approval re-derives delta from the current book and requires `inventory.approve` | Prevents fake corrections; respects movements since the count |
| D34 | Lot disposition (quarantined/recalled) is org-wide; quarantine needs `inventory.manage`, recall/release need `inventory.approve`; stock is never deleted by a disposition | BP19 |
| D35 | Expiry-day usability is a policy switch `expiry_last_day_usable` (default true) | Cold-chain interpretation Requires external validation |
| D36 | Appointments (any channel) consume `online_capacity`; walk-ins consume the day's summed `walkin_capacity` via queue entries; overflow is a recorded staff decision | BP17 separation of bookings and arrivals |
| D37 | Session row `FOR UPDATE` is the single serialisation point for book/cancel/reschedule (two-session moves lock in id order) | T02; verified by a mutation run that removed the lock and failed |
| D38 | Ticket numbers come from a per-(clinic, local day) counter row updated under lock; label `MMDD-NNN`; never reused | Gapless, unique under concurrency |
| D39 | A ticket that leaves/cancels returns its appointment to `confirmed` (re-checkable); `fulfilled` is set only when the encounter completes with an outcome (deferral counts) | BP17: fulfilled != every dose given |
| D40 | Public waiting-room display is anonymous but returns only ticket labels and stations; rate-limited at the API | BP17 |
| D41 | Realtime is not used yet; UIs poll (staff 15 s, display 5 s) and always show a "last updated" time | Supabase Realtime not verifiable locally; honesty about staleness (BP17) |
| D43 | UI pass (2026-09-30): "quiet clinic paper" design world; self-hosted Atkinson Hyperlegible Next (OFL, `@fontsource`), warm off-white surfaces, deep-teal action colour, slashed-zero tabular numerals for record numbers/tickets/dates | Legibility for tired staff and low-vision guardians; the blueprint asked for Atkinson Hyperlegible |
| D44 | Staff get a persistent shell (sidebar on desktop, scrolling tab row on mobile) with role-derived items; guardians get a single 48rem column; pages use unboxed `Section`s, and cards only for self-contained tasks | Removes the card-wall dashboard feel; navigation by task |
| D45 | Notices are fully bordered and icon-led with no coloured side stripe; status is always text + icon | Design-floor ban on side stripes; BP35 colour-not-alone |
| D46 | Queue rows keep primary actions inline and put reason-requiring actions (hold/left/cancel/prioritise) behind "More actions" | Reduces mis-taps in a busy clinic while keeping audit reasons mandatory |
| D42 | The durable outbox exists from M05 (`private.outbox_jobs`, dedupe key unique per org); commands only enqueue, never call providers | BP31 |
| D47 | A certificate is a separate lifecycle (`pending` -> `issued` -> `revoked`) over an immutable JSON snapshot plus `certificate_items` links to the exact revisions; the snapshot hash is stored; only verified, active, non-voided revisions qualify | BP20, T23 |
| D48 | The PDF is rendered by the app from the frozen snapshot and stored as `bytea` in `private.certificate_documents` (checked: `%PDF-` header, size, SHA-256); reprints return the same bytes. Storage buckets are unverified locally, so the database is the store for now | BP20; L27 |
| D49 | The verification token is 256 random bits shown only inside the PDF/QR; only its SHA-256 is stored; it is issued by a separate non-idempotent call so it never lands in a command receipt; a retry while pending rotates it | BP33 forged-certificate threat |
| D50 | Public verification returns status (valid / under review / revoked), number, clinic and issue date only; unknown, malformed and pending tokens are indistinguishable | BP20 minimal public response |
| D51 | Corrections that change what a certificate shows (date, product, lot, child, void, verification) flag it `under review` by trigger in the same transaction; the snapshot is never rewritten; revoke or replace are explicit issuer actions | T23 |
| D52 | Messages are created only by the outbox worker from fixed templates for verified guardians (full access); no free text, no clinical guidance; dedupe per recipient and event | BP22 |
| D53 | `private.process_outbox` is bounded, uses `FOR UPDATE SKIP LOCKED`, retries with 2^n minute backoff up to 5 attempts, fails immediately on unknown job types, reclaims expired locks; it is not executable by API roles and is called by a worker connection (`CVSRS_WORKER_DB_URL`) | BP22, BP31 |
| D54 | Reports are database functions over current revisions, the queue and the ledger, each returning its metric definitions and a definitions version; none returns names or identifiers | F33; BP31 |
| D55 | Small-cell suppression applies to exports only (staff already see exact figures on screen); counts between 1 and threshold-1 are withheld and totals that would allow deduction are withheld too; threshold is a setting, default off, value needs the privacy owner | BP27 |
| D56 | Paper tallies are append-only and never edit vaccination or stock records; the reconciliation report shows differences for a person to explain | BP41 |
| D57 | Restore drill = dump, restore to a fresh database, then verify counts, ledger, certificate hashes/checksums, guard triggers, RLS and API-role privileges; it must fail when a certificate is tampered with (checked) | BP43 |
| D58 | Stock transfers use a per-clinic in-transit location and two ledger transactions; short deliveries stay in transit until a person other than the sender writes them off or returns them | F13 |
| D59 | Cold-chain limits are recorded policy (approver + policy reference), append-only; readings keep the limits in force when taken; an excursion is flagged, never auto-quarantined | F14; BP19 |
| D60 | SMS is optional: consent needs an in-person number check, wording is fixed and carries no child or clinical detail, the database owns the delivery state machine and provider callbacks are idempotent and order-tolerant; the provider adapter is replaceable and only a sandbox exists | F18; BP22 |
| D61 | Catch-up plans are staff-authored and second-person reviewed and are inert: they never touch the engine, credits or bookings | F11; BP17 |
| D62 | Family check-ins are off until the clinical lead records the safety notice; the system supplies no default wording and does not answer or triage | F20 |
| D63 | The follow-up worklist stores engine results per child as snapshots (bounded on-demand refresh, invalidated by new vaccinations, holds and schedule changes) and never computes anything the schedule does not say | F10 |
| D64 | Contact numbers appear on the worklist only for bhw.followup holders, and each listing is audited | BP33 |
| D65 | Holds are placed by clinical staff and released only by a clinical lead; a hold blocks planned doses and flags every requirement for staff review | F09; T07 |
| D66 | The privacy-notice gate wraps the two guardian self-service commands (originals renamed and made uncallable) instead of relying on the UI | BP33 |
| D67 | CSP is built per request in `src/proxy.ts` with a nonce and `strict-dynamic`; application responses are never cacheable | BP32 |
| D68 | A sweep test enumerates every command executable by API roles, so a new function that leaks to an unrelated user or crashes on odd input fails the build without anyone writing a test for it; intentionally open commands must be listed with a reason | BP31 |
| D69 | Record transfer moves the enrollment, not the data: one child, one organization; access follows the enrollment; consent + release + acceptance are three separate actors/steps | F26; BP33 |
| D70 | Offline clinical writes are deferred rather than half-built: storing children's records on devices needs an agreed threat model (enrolment, encryption at rest, revocation/wipe, conflict handling); shipping less than that would create a privacy risk larger than the convenience | F22; BP31 |
| D71 | CV409 (state conflict) messages authored by our functions are shown to users because they are actionable and contain no record data; all other database messages stay hidden | BP40 |
| D72 | Care information has no built-in text; it needs an author, a different approver and a source reference, is frozen once submitted and shown only when active | F19; BP33 |
| D73 | The audit trail is organization-level (rows carry the organization, not a clinic), so audit.read at any clinic reads the organization's trail; searches are themselves audited | P39; T32 |
| D74 | Operations status never infers health: it reports recorded checks and live queue counts, and "unknown" when nothing was recorded | P40 |
