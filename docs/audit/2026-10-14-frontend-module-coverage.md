# Frontend and source module coverage — 14 October 2026

Snapshot: current working tree, including existing user changes. This is a finite module/caller inventory and source-contract audit, not a claim of zero defects or complete branch coverage. No application source, database or browser was changed/run by this final inventory pass.

## Method and finite scope

- Parsed every **331 TypeScript/TSX source module** under `src` with the installed TypeScript AST parser; asserted zero parse diagnostics.
- Accounted for all **39 page entry modules**, all **20 shared component modules**, all **3 client-library modules**, other app forms/hooks/helpers, and backend dependencies. TypeScript AST traversal across `src`, `scripts` and `tests` records static imports, type-only imports, re-exports and literal dynamic `import()` edges; exact incoming importers and outgoing local imports are recorded below.
- Frontend source/import/contract review covers 136 modules (all frontend modules plus `src/lib/format.ts`); 195 remaining API/auth/backend modules are explicitly accounted for and assigned to the parallel backend audit, rather than excluded.
- Followed the local import graph recursively: 157 modules are reachable from frontend/page/shared entry modules. This includes server viewer, database, auth, certificate, validation, configuration and security helpers; server-side page dependencies are not mislabeled browser bundles.
- AST-extracted client request sites and cross-checked literal/template paths against actual route files and exported methods. Found 122 frontend request sites: 103 directly resolvable paths, with no missing endpoint or HTTP-method mismatch. Dynamic helper arguments are enumerated and manually traced below. Payload checks compare actual submitted fields, discriminators and optional/null behavior against the imported Zod schemas; database/SDK semantics remain governed by the backend audit and runtime tests.
- Test column records direct source-module imports in tests. Browser journeys frequently exercise routes without importing their source; absence of a direct test import is not absence of journey coverage.
- Source fingerprints use the first 12 characters of SHA-256 to distinguish this snapshot from later changes. Full fingerprints and AST extraction are retained in ignored `.local/frontend-inventory.json`; the module accounting is self-contained here.
- The complementary [backend/shared-library audit](2026-10-14-backend-module-coverage.md) supplies semantic source review for all 48 backend/shared library modules, plus the route and RPC boundary inventory. `src/proxy.ts` and `src/instrumentation.ts` received explicit coordinating-agent source review: request CSP/session refresh, production configuration failures, and Node-only worker startup. The remaining three client libraries and `format.ts` are covered here, accounting for all 52 library modules.

Migration `0046_search_inactive_records.sql`, shared `recordStatusChip`, and the existing client/download helpers preserve their contracts. 2. Merge cancellation focus was verified for both survivor choices and fixed with `useConfirmStep`. Typed merge evidence remains required; focused unit tests passed 56/56 with lint passing. A later real-browser opened-state journey verifies both cancellations.
3. This pass identified a remaining transfer-unit label defect: `SendForm` hardcoded “Quantity (vials)” while products permit other stock units. The coordinating agent reproduced a failing render regression and changed the label to “Quantity (stock units)”, including the returned lot unit in the selection label. Its final check passed 593 unit tests, type checking and lint; final build also passed. A real transfer-page check confirmed its intentional empty state with only one clinic, not browser execution of a transfer form. Runtime results are coordinating-agent evidence, not newly run by this source pass.
4. No further definite client endpoint/method or submitted-body/schema mismatch was found in the reviewed caller families. This is a source review conclusion, not universal runtime proof.
5. Remaining manual gate: actual screen-reader use with a human is pending. Root-owned live evidence covers normal journeys, opened forms, rehearsal and actual browser zoom; this source pass makes no new hardware or assistive-technology claim.
