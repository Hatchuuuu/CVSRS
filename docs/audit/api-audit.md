# API and security architecture audit (2026-09-30)

Scope: read-only review of all 124 `src/app/api/v1/**/route.ts` files (145 exported handlers), the two `/auth` and `/dev` POST routes, sign-in/MFA UI, shared API, validation and database adapters, proxy, worker, deployment configuration, SQL authorization helpers, tests, and operations documentation. No live Supabase or production traffic was available. Findings below distinguish code-observed defects from deployment gates and future improvements.

## Findings

| ID | Severity / category | Finding, impact, and action |
|---|---|---|
| API-01 | **High · production gate** | Rate-limit identity is the first `x-forwarded-for` value supplied to the handler, while counters live in a process-local map. Unless the ingress strips and replaces that header, clients can rotate its value; across instances, each instance enforces its own count. This affects public token checks, QR resolution, report/PDF downloads, mutations, and SMS callbacks. Place limits at a trusted ingress using its normalized client address and shared state; add per-user and per-token budgets for sensitive authenticated reads. Evidence: [`handler.ts`](../../src/lib/api/handler.ts#L32), [`rate-limit.ts`](../../src/lib/security/rate-limit.ts#L3), [`sms/route.ts`](../../src/app/api/v1/webhooks/sms/route.ts#L13). L3 already records the shared-state limitation in [`known-limitations.md`](../implementation/known-limitations.md#L7). |
| API-02 | **High · production gate** | SMS callback opens a new privileged database connection before it validates the signature, and reads the entire body before checking its 10,000-character limit. Anonymous invalid traffic can therefore consume DB connections and request memory. Enforce byte-size at ingress/streaming read, reject missing/bad HMAC before opening DB, pool or isolate worker connections, and keep webhook DB credentials restricted to its needed function. Evidence: [`sms/route.ts`](../../src/app/api/v1/webhooks/sms/route.ts#L13), [`webhook.ts`](../../src/lib/sms/webhook.ts#L21), [`outbox.ts`](../../src/lib/worker/outbox.ts#L10). No production SMS provider is configured yet per [`external-validation.md`](../implementation/external-validation.md#L11). |
| API-03 | **High · production gate** | Supabase Auth, MFA claim propagation, PostgREST argument marshalling and request-header behavior have not been exercised against a real project. Local tests mark every session `aal2`, so they cannot prove staff MFA enforcement in deployment. Run staging end-to-end tests through Supabase for guardian and staff roles, MFA enrolled/unenrolled states, direct RPC calls, token expiry, cookie refresh and denied grants before real-data use. Evidence: [`local.ts`](../../src/lib/db/local.ts#L8), [`supabase.ts`](../../src/lib/db/supabase.ts#L23), [`0001_foundation.sql`](../../supabase/migrations/0001_foundation.sql#L292), [`known-limitations.md`](../implementation/known-limitations.md#L5). |
| API-04 | **Medium · production gate** | The app accepts a privileged `CVSRS_WORKER_DB_URL` in the web process and starts the outbox poller from web instrumentation; the webhook also uses this URL. This broadens the effect of a web-runtime compromise and makes processing depend on web process lifetime. Run the worker in a separate runtime with a least-privilege database role and a scheduled worker on serverless hosting. Evidence: [`instrumentation.ts`](../../src/instrumentation.ts#L1), [`outbox.ts`](../../src/lib/worker/outbox.ts#L10), [`README.md`](../../README.md#L32). |
| API-05 | **Medium · production gate** | Certificate QR links use `new URL(req.url).origin` when `CVSRS_PUBLIC_URL` is missing. If host/proxy input is misconfigured, an issued PDF may permanently contain a wrong verification host. Require and validate the canonical HTTPS public URL at production startup, and test issuance behind the chosen proxy. Evidence: [`service.ts`](../../src/lib/certificates/service.ts#L7), [`README.md`](../../README.md#L32). |
| API-06 | **Medium · recommended** | Generic JSON routes parse a complete body with `req.json()` and have no application-level byte limit; nested/import payloads can spend CPU and memory before Zod or database limits run. Add a route-appropriate request-size cap at the ingress and wrapper, especially schedule import; retain server-side schema and SQL validation. Evidence: [`handler.ts`](../../src/lib/api/handler.ts#L58), [`clinical.ts`](../../src/lib/validation/clinical.ts#L45). |
| API-07 | **Medium · recommended** | `isSameOrigin` compares the `Origin` host with the request `Host` only, without scheme or an allow-listed canonical origin. This relies on accurate Host forwarding and HSTS. Pin allowed HTTPS origins in production, handle the trusted proxy explicitly, and test hostile Host/scheme combinations. Evidence: [`origin.ts`](../../src/lib/security/origin.ts#L6), [`next.config.ts`](../../next.config.ts#L14), [`security.test.ts`](../../tests/unit/security.test.ts#L8). No direct exploit is claimed from this code alone. |
| API-08 | **Low · recommended** | Numeric query limits use `Math.min(Number(value) || default, max)` without a positive-integer check. Negative, decimal and `Infinity` inputs can reach the database; SQL clamps some functions, but behavior and error shapes differ by endpoint. Centralize bounded query parsing for message, audit, follow-up and temperature reads. Evidence: [`messages/route.ts`](../../src/app/api/v1/me/messages/route.ts#L3), [`audit/route.ts`](../../src/app/api/v1/clinics/%5BclinicId%5D/audit/route.ts#L11), [`followup/route.ts`](../../src/app/api/v1/clinics/%5BclinicId%5D/followup/route.ts#L3), [`temperature/route.ts`](../../src/app/api/v1/clinics/%5BclinicId%5D/stock/temperature/route.ts#L4), [`0024_config_content_audit_ops.sql`](../../supabase/migrations/0024_config_content_audit_ops.sql#L216). |
| API-09 | **Medium · production gate** | Aggregate export suppression defaults to zero, so small positive counts are visible until a privacy owner selects a threshold. The database enforces a max 366-day report range and export audit, and CSV cells are formula-neutralized; the remaining decision is policy. Choose and verify the threshold before exporting real clinic data. Evidence: [`0018_reports.sql`](../../supabase/migrations/0018_reports.sql#L9), [`0018_reports.sql`](../../supabase/migrations/0018_reports.sql#L55), [`0018_reports.sql`](../../supabase/migrations/0018_reports.sql#L60), [`csv.ts`](../../src/lib/reports/csv.ts#L4), [`external-validation.md`](../implementation/external-validation.md#L16). |
| API-10 | **Low · recommended** | The bespoke download, CSV and webhook routes return different error envelopes and retry headers from `api()`. Keep binary responses, but share request-ID, safe-error and rate-limit response helpers so clients and monitoring see consistent codes. Evidence: [`handler.ts`](../../src/lib/api/handler.ts#L36), [`download/route.ts`](../../src/app/api/v1/certificates/%5BcertificateId%5D/download/route.ts#L11), [`export/route.ts`](../../src/app/api/v1/clinics/%5BclinicId%5D/reports/%5Bname%5D/export/route.ts#L15), [`sms/route.ts`](../../src/app/api/v1/webhooks/sms/route.ts#L12). |
| API-11 | **Low · future** | Several list reads have fixed windows or no cursor pagination, limiting large-clinic use; this is already documented for search and appointments. Add cursors after representative staging load measurements. Evidence: [`known-limitations.md`](../implementation/known-limitations.md#L11), [`known-limitations.md`](../implementation/known-limitations.md#L29), [`children/route.ts`](../../src/app/api/v1/clinics/%5BclinicId%5D/children/route.ts#L9). |

## Validation and verification gaps

- Zod schemas cover declared mutation bodies, strict fields, UUIDs, dates, enum vocabulary and lengths; SQL still owns clinical and state checks. The wrapper validates dynamic parameter names ending in `Id`; other path values such as report names and certificate tokens are checked in their route handlers. See [`handler.ts`](../../src/lib/api/handler.ts#L51), [`schemas.ts`](../../src/lib/validation/schemas.ts#L10), [`reports/route.ts`](../../src/app/api/v1/clinics/%5BclinicId%5D/reports/%5Bname%5D/route.ts#L8), [`verify/route.ts`](../../src/app/api/v1/verify/%5Btoken%5D/route.ts#L5).
- Safe SQLSTATE mapping hides raw database text except application-authored CV409/CV422 messages; unknown exceptions expose only a request ID and safe 500 text. See [`errors.ts`](../../src/lib/api/errors.ts#L30), [`handler.ts`](../../src/lib/api/handler.ts#L83). SQL capability denials currently roll back and lack a separate security-event sink, as tracked in [`known-limitations.md`](../implementation/known-limitations.md#L8).
- Unit tests cover origin, in-memory limiting, error mapping, CSP and webhook HMAC; DB tests cover many commands and role boundaries. The searched test tree has no HTTP-level route tests for wrapper sequencing, cookie refresh, custom response envelopes or trusted-proxy headers. Add a small HTTP integration suite and Supabase staging contract tests. See [`security.test.ts`](../../tests/unit/security.test.ts#L8), [`sms.test.ts`](../../tests/unit/sms.test.ts#L43), [`csp.test.ts`](../../tests/unit/csp.test.ts#L2), [`known-limitations.md`](../implementation/known-limitations.md#L5).
- CI is not configured and production backup/restore, load and live provider behavior remain externally unverified. See [`known-limitations.md`](../implementation/known-limitations.md#L18), [`known-limitations.md`](../implementation/known-limitations.md#L37), [`known-limitations.md`](../implementation/known-limitations.md#L38). This audit ran no database reset, seed, worker or traffic-generating check.
