# Presentation Readiness Audit

Date: 2026-10-08. Scope: running CVSRS locally and presenting it to a professor with the synthetic demo (`docs/operations/professor-demo.md`). It follows the [local-readiness report](2026-10-08-local-readiness.md). No new product capability, migration or clinical rule was added. Light-only theming is the owner's decision (2026-10-02) and was kept.

## Method

Every gate was run on the current working tree, the demo was prepared exactly as the presenter would prepare it, and the presentation sequence was played in a browser, once by hand at 1366×768 and once automated. The automated pass is now a command (`npm run demo:rehearse`), so the same check can be repeated before presenting.

## Remaining risks for the presentation

- Docker Desktop must be running, and `demo:prepare` must run on the presentation day: the demo's session is for the day it was prepared.
- The demo runs `next dev`. A screen the audience has not seen yet compiles on first open; `demo:rehearse` beforehand opens all of them.
- Staff are signed out after 15 minutes without input (a security setting, kept). A role used early and again late in the talk may need one fresh sign-in and code; the warning appears a minute before.
- Schedule rows show the fixture codes (A1, B1, G1) and fictional vaccines; this is deliberate, the software ships no clinical rules.
- Hosted deployment, real email/SMS, and clinical acceptance remain out of scope (see the local-readiness report).
